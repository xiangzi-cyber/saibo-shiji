# 赛博史记线上卡片化 SOP

这份 SOP 复盘的是我们把《赛博史记》四宫格漫画变成线上漫画卡片的流程。范围只包含线上图片与网站卡片，不包含 A5/PDF 打印导出。

## 目标

把一张已经完成的四宫格漫画，转化成网站上可以被快速浏览、点击查看、持续收藏的线上卡片。卡片不是给漫画套一个壳，而是把漫画的故事、情绪和创作意图压缩成一个稳定的阅读入口。

完成后的线上卡片必须包含：

- 四宫格漫画原图：用于点击查看完整作品。
- 线上封面图：用于卡片网格快速加载。
- 期数、标题、创作日期：用于系列索引。
- 故事简介：用一到两句话讲清本期漫画的核心。
- 可点击入口：打开原图，不裁切、不替换原作。

## 核心原则

### 1. 原作不动，卡片解释原作

四宫格漫画是创作证据，也是最重要的视觉主体。线上卡片只负责帮助读者进入作品，不重新生成漫画、不改角色、不把漫画里的文字变成另一个版本。

### 2. 固定骨架，单期定制

所有卡片共享同一套信息骨架：

`封面图 -> 日期/期数 -> 标题 -> 故事简介 -> 查看全图`

每一期可以变化的是故事简介、封面裁切、卡片主题语气和少量视觉强调。这样网站能保持系列感，又不会把每期做成互不相干的页面。

### 3. 线上优先，不混入打印规则

线上卡片只服务浏览体验：

- 首屏卡片优先加载，后续卡片懒加载。
- 封面图要轻，原图用于 lightbox。
- 文案要适合屏幕阅读，不按 A5 纸张安全区排版。
- 不导出 PDF，不检查打印边距，除非用户明确要求。

## 线上卡片化流程

### Step 1. 收集输入

每期新增前先收齐四类材料：

- 漫画原图：例如 `comics/ep13_comic.jpg`。
- 创作日期：例如 `2026.06.01`。
- 期数与标题：例如 `第 13 期`、`赛博史记之永远的乐园`。
- 创作说明或提示词：用于提炼故事简介和卡片气质。

如果用户只给了口述故事，也先转写成三句话：

- 发生了什么。
- 情绪是什么。
- 读者最后应该记住什么。

### Step 2. 提炼卡片 DNA

每张卡片先提炼五个字段：

| 字段 | 作用 | 示例 |
| --- | --- | --- |
| 故事核 | 一句话讲清剧情 | 猫咪大老板在 AGI Bar 茶杯里享受永远的乐园 |
| 情绪 | 决定文案和视觉语气 | 微醺、放松、童心、奢华 |
| 视觉锚点 | 让封面和卡片可识别 | 茶杯、霓虹、游乐园、机器人秘书 |
| 点题句 | 让故事有余味 | 额度会重置，快乐不重置 |
| 系列位置 | 说明这期在作品集里的角色 | 最新一期、节日更新、主题转折 |

这一步决定卡片是不是有“内容理解”。不要直接把提示词照搬成简介。

### Step 3. 生成线上封面

线上封面用于网格加载，目标是快、清晰、无水印。

建议规格：

- 方形封面：`640 x 640` 或接近尺寸。
- 文件路径：`comics/covers/epXX_cover.jpg`。
- 原图路径：`comics/epXX_comic.jpg`。
- 封面可以从原图裁切或缩放生成，但不能裁掉主角、标题和关键分镜。

封面检查：

- 没有水印、聊天截图角标、平台标记。
- 缩小后仍能看出本期主题。
- 色相、饱和度和原图基本一致，不出现明显灰化、偏色、过度压缩。
- 原图不被覆盖成低清封面。

### Step 4. 写卡片文案

文案遵循“短、准、有余味”：

- 标题保留作品名，不为了 SEO 改写。
- 简介控制在 45-90 个中文字符。
- 先说画面发生了什么，再说它表达了什么。
- 不解释所有梗，只保留最能帮助读者进入作品的入口。

示例：

```text
猫咪大老板窝在 AGI Bar 茶杯里，机器人秘书端来发光鸡尾酒。额度会重置，快乐不重置，愿你永远有心中的游乐园。
```

### Step 5. 插入网站卡片

在 `index.html` 的 `.comic-grid` 中新增一张 `article.comic-card`。新增期数通常放在最前面。

必须同步：

- `openLightbox('comics/epXX_comic.jpg')`
- `img src="comics/covers/epXX_cover.jpg"`
- `img alt="赛博史记第XX期"`
- `date-badge`
- `episode-badge`
- `card-title`
- `card-desc`
- `btn-view`

首张卡片可以使用：

```html
loading="eager" decoding="async" fetchpriority="high"
```

其他卡片使用：

```html
loading="lazy" decoding="async"
```

### Step 6. 线上 QA

每次更新至少检查这些点：

- 卡片网格能显示新封面。
- 点击封面和按钮都能打开原图。
- 原图完整显示，没有把四宫格裁切成封面。
- 标题、日期、简介没有错别字。
- 手机宽度下文字不溢出，按钮不压住简介。
- 封面和原图无水印，且不是浏览器缓存里的旧图。
- 颜色没有因为压缩、错误转换或误用旧图而明显变灰。

### Step 7. 提交与发布

提交前确认只包含本次相关文件：

- `index.html`
- `style.css` 如果样式有变化
- `comics/epXX_comic.*`
- `comics/covers/epXX_cover.*`
- SOP、Skill 或说明图等文档文件

推送前用 `git status --short` 检查未跟踪临时文件。不要把 PDF、临时 QA 截图、浏览器缓存目录混进线上卡片更新。

## 常见故障与修复

### 颜色突然变灰或色相不一致

优先排查：

- 是否把低清封面覆盖到了原图。
- 是否从 PDF 渲染页、聊天截图或压缩预览图重新生成了线上图。
- 是否重复 JPEG 压缩导致饱和度和文字边缘下降。
- 浏览器是否还在显示缓存旧图。

修复方式：

- 回到用户给的原始漫画图重新生成封面。
- 原图只做格式和尺寸必要处理，不做滤镜、自动增强或统一调色。
- 重新打开页面时加版本参数或清缓存验证。

### 字不清楚

优先排查：

- 封面是否太小，导致站点里又二次放大。
- 是否裁切到了含关键文字的区域。
- 是否把 `cover` 用在原图查看层。

修复方式：

- 网格封面用清晰方图，lightbox 永远加载原图。
- 原图展示使用完整图片，不用封面替代。

### 水印还在

优先排查：

- 线上 `comics/` 和 `comics/covers/` 是否都替换。
- 页面是不是引用了旧路径。
- 本地预览或浏览器是否缓存旧图。
- 是否只更新了网站，没更新实际被读取的资源。

修复方式：

- 对比源图、线上原图、封面图的底部和角落。
- 重新生成封面后刷新缓存。
- 推送后用部署站点打开对应图片 URL 直接确认。
